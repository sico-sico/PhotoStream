feat(cache): persist parsed EXIF in SQLite; polish wall interaction

Caching a local SQLite database was the right instinct, but measurement put it
somewhere other than thumbnails. Opening the 3226-photo sample folder took
1296 ms, broken down as:

  readdir + filter        3 ms
  stat x 3226            28 ms
  EXIF parse x 3226    1178 ms   <- 91%

Thumbnails are generated on demand, never during open, and the existing on-disk
WebP cache is already content-addressed by path+mtime+size. The real cost is
that every photo needs its first 512 KB read to find the capture date: 1.6 GB
per scan, measured at 422 ms for the reads alone against 79 ms for a 32 KB
prefix.

- src/main/metadata-cache.ts stores path+mtime+size -> {width,height,takenAt,
  orientation} in SQLite. Keyed by all three, so a re-export in Lightroom (same
  path, new mtime and size) is a miss, never a stale hit.
- node:sqlite ships with Electron's Node 24, so this adds no dependency; it was
  verified inside the packaged main process.
- WAL + synchronous=NORMAL: a lost row only costs a re-read.
- Rows for files that vanished are pruned once per scan, so the database does
  not grow with every folder ever opened.
- Every method swallows its own failure: an unusable database degrades to
  "no cache" rather than blocking the scan.

Result on the same folder: 1561 ms cold -> 240 ms after a process restart
(6.5x) -> 135 ms within one session (11.6x). The database is 0.8 MB.

Where everything lives: PhotoStreamData/ next to the exe in a packaged build,
or under the userData override in development. That folder holds settings.json,
metadata.db (+ WAL sidecar files) and thumbs/.

Wall interaction
- Keyboard steps and auto-scroll now ease over 220 ms (.world.settling);
  dragging and wheel zoom stay instant, because a transition there would trail
  the pointer. Honours prefers-reduced-motion.
- Tiles lift 4% with a shadow on hover. The position had to move from an inline
  transform to --tile-x/--tile-y custom properties: an inline transform beats
  the .tile:hover rule, which silently disabled the effect.
- Zooming out re-lays the wall out at viewport/scale width, so the columns fill
  the window instead of leaving empty bands at both sides. Measured: at 0.22
  zoom the world width goes 1600 -> 7273 px against a 1600 px stage.
